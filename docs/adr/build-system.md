# ADR: Build System and Compilation

## Status: Accepted

## Decision Drivers
- PHP extension must compile on macOS (Apple Silicon) and Linux
- PHP 8.5 uses `-std=gnu23` by default; our code requires C11 features (`_Static_assert`, `_Alignof`, `<stdatomic.h>`)
- PHP extension convention requires `config.h` include in every .c file

## Context

php-beacon-extension is a C extension for PHP-FPM. The build system must:
1. Probe PHP version and headers
2. Probe system features (`<stdatomic.h>`, `<sys/shm.h>`, `<sys/prctl.h>`, zlib)
3. Set compile flags compatible with both PHP's build system and C11

PHP's `phpize` generates a Makefile that passes `-std=gnu23` (C23 with GNU extensions). Our code uses C11 features. The last `-std=` flag wins, so our `-std=c11` in `config.m4` overrides PHP's default.

## Decisions

### D1: autoconf config.m4

Use `PHP_NEW_EXTENSION` with `config.m4` (autoconf). Probe:
- PHP version >= 8.0 (`AC_MSG_CHECKING` + `PHP_FPM`)
- `<stdatomic.h>` (`AC_CHECK_HEADER`)
- `<sys/shm.h>`, `<sys/ipc.h>` (sysv shm)
- `<sys/prctl.h>` (Linux process naming, optional on macOS)
- zlib (`AC_CHECK_LIB` for `crc32`)

CFLAGS: `-D_GNU_SOURCE -std=c11 -Wall -Wextra`

**Industry benchmark:** Swoole (`config.m4` probes PHP version, pthread, pcre, openssl), Yar (`config.m4` probes PHP version, msgpack)

**Alternatives considered:**
- CMake: Not standard for PHP extensions; PHP ecosystem uses autoconf
- Hand-written Makefile: Loses PHP integration (phpize, pear install)

### D2: config.h include pattern

Every .c file starts with:
```c
#ifdef HAVE_CONFIG_H
#include "config.h"
#endif
```

`config.h` (generated by `./configure`) defines `HAVE_STDINT_H`, `HAVE_ZLIB_CRC32`, etc. PHP headers (`zend_types.h`) conditionally include system headers based on these macros. Without `config.h`, PHP headers may not properly set up integer types, causing `arm_neon.h` errors on macOS ARM.

**Industry benchmark:** All PHP extensions (Swoole, Yar, redis, curl) follow this pattern.

### D3: _Alignof instead of alignof

Use `_Alignof` (C11 keyword) instead of `alignof` (C23 keyword / `<stdalign.h>` macro). Since we compile with `-std=c11` (overriding PHP's `-std=gnu23`), `alignof` is not available without `<stdalign.h>`.

**Industry benchmark:** Linux kernel uses `__alignof__` (GCC extension). C11 standard uses `_Alignof`. C23 makes `alignof` a keyword.

## Consequences

- Build system is standard PHP extension autoconf, compatible with `phpize` and `pear install`
- `config.h` include is mandatory in every .c file
- `_Alignof` is used instead of `alignof` for C11 compliance
- macOS ARM and Linux both compile cleanly
